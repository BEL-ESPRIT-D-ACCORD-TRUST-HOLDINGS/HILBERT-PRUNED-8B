# semif86

`semif86` is a single native engine for SemIf's `direct-options-v1` decisions on
the pinned Qwen3.5-4B checkpoint. It is written in C11 with a CUDA backend built
for **sm_86** (RTX 3090, RTX 30xx and A-series Ampere cards). It does not use
Python, PyTorch, cuBLAS or llama.cpp at run time. It reads the Hugging Face
snapshot directory directly: `config.json`, `tokenizer.json` and the sharded
safetensors.

It consolidates five repositories into one clean-room implementation. The
contract it implements is in [SPEC.md](SPEC.md).

```
rows.jsonl ─▶ validate ─▶ prompt bytes ─▶ byte-level BPE ─▶ Qwen3.5 hybrid decoder ─▶ A..P slot logits ─▶ softmax
             (SemIf)     (sha256 match)   (NFC + regex)     (24 DeltaNet + 8 gated attn)   (last position only)
```

## What is verified, and how

| Claim | Evidence | Where |
|---|---|---|
| Prompt bytes, token ids and answer slots equal SemIf's Python path | **1,029/1,029** committed benchmark rows (authored144, perturbations108, shape777; prompts up to ~1,900 tokens) reproduce the recorded `prompt_sha256`, `input_tokens` and slot ids | `tools/check_prompts.py` |
| Tokenizer equals HF `tokenizers` | 423/423 strings (fixed edge cases plus 400 random strings: NFC, Hangul, emoji, CR/LF runs, contractions, added tokens, control characters) | `tools/parity.py` |
| CPU forward pass equals PyTorch | Tiny random Qwen3.5 checkpoints (f32 and bf16 weights, 1 to 3 shards, both weight-name prefixes, prefix snapshot/restore): max \|Δlogit\| ≤ 7e-6. Direct and shared `score` rows match the probabilities from `semif_phase1` encoding + PyTorch to ≤ 2e-7 | `tools/parity.py` |
| Real weights | CPU engine (float32) on the real Qwen3.5-4B, on the 3 shortest authored rows, against SemIf's committed RTX 3090 bf16 run: logits within 0.1 (the reference is bf16-rounded), probabilities within 0.02, argmax 3/3 | one-off run (needs the 9 GB weights; not automated) |
| CUDA backend compiles for sm_86 | `nvcc 12.8 -gencode arch=compute_86,code=sm_86`, no warnings, no register spills | `make cuda` |
| CUDA backend is numerically right | **Not executed yet. The environment that built this has no GPU.** `semif86 selftest` checks every GEMM path against a double-precision reference, compares full CUDA forward passes (including prefix snapshot/restore) with the CPU reference, and reports prefill throughput | run on the 3090 |

Run `selftest` before trusting CUDA numbers.

## Build

```bash
make                                  # CPU reference build  -> build/semif86 (gcc/clang + OpenMP)
make cuda CUDA_HOME=/usr/local/cuda   # sm_86 build          -> build/semif86-cuda
make test                             # model-free unit tests
```

The CUDA build needs a CUDA 12.x toolkit. It links only against `cudart`.

## Run

```bash
huggingface-cli download Qwen/Qwen3.5-4B --revision 851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a --local-dir qwen35-4b

# 1. check kernels and the whole forward pass against the CPU reference (about 20-60 s of CPU time)
build/semif86-cuda selftest --model qwen35-4b --tokens 64

# 2. score rows (same input and output schema as semif-score; the output file must be new)
build/semif86-cuda score --model qwen35-4b --revision 851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a \
  --input ../examples/decisions.jsonl --output results.jsonl            # --mode shared for one prefill

# 3. serve
build/semif86-cuda serve --model qwen35-4b --revision 851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a --port 8086
curl -s localhost:8086/v1/decide --data-binary @<(head -1 ../examples/decisions.jsonl)
curl -s localhost:8086/v1/decide --data-binary '{"rows": [ ... ]}'     # shared-prefix batch
```

Other commands:

- `semif86 prompt --model DIR --input rows.jsonl` prints the sha256, token
  count and slot ids for each row. It needs no weights.
- `semif86 tokenize --model DIR < text` prints token ids.
- `semif86 logits --model DIR --tokens "…" --ids "…" [--split N]` prints raw
  logits for parity work.

`--backend cpu` runs the float32 reference on any build. It is exact but slow:
about 45 s for three ~130-token rows on 4 cores.

Result rows carry `id`, `option_ids`, `probabilities`, `option_logits`,
`input_tokens`, `prompt_sha256` and `prompt_version`, plus `model` metadata
naming the backend and the exact `--revision`. Shared mode adds
`shared_timing`. As in SemIf, probabilities are conditional option scores, not
calibrated confidence.

## Layout

| File | Role |
|---|---|
| `src/prompt.c` | Row validation, `direct-options-v1` prompt bytes, answer-slot boundary checks (SPEC §1-3) |
| `src/json.c` | Strict JSON reader and a writer byte-compatible with Python `json.dumps(ensure_ascii=False)`, including float `repr` |
| `src/tokenizer.c`, `src/unicode.c` | Byte-level BPE with the Qwen pre-tokenizer regex hand-compiled, and NFC. `unicode_tables.h` is generated by `tools/gen_unicode_tables.py` |
| `src/safetensors.c`, `src/model.c` | mmap'd sharded safetensors, config, weight binding (SPEC §4.4) |
| `src/cpu_backend.c` | float32 reference forward pass |
| `src/cuda_backend.cu` | sm_86 forward pass and `selftest` |
| `src/ops_common.h` | Scalar math shared by both backends (bf16, silu, softplus, sigmoid) |
| `src/engine.c` | Direct scoring, and shared scoring over the longest common token prefix with state snapshot/restore |
| `src/http.c` | Blocking HTTP/1.1 server: `POST /v1/decide`, `GET /healthz` |

CUDA kernels:

- **GEMM.** bf16 WMMA m16n16k16 tensor-core tiles (64×64×32) with float32
  accumulation, a warp-per-column GEMV for fewer than 32 rows, and a scalar
  fallback.
- **Gated attention.** Online softmax, 8 queries per block, K/V tiles in
  shared memory, sigmoid output gate fused in.
- **Gated DeltaNet.** Recurrence with each 128-row state column split across 2
  lanes and held in registers (168 regs, no spill). Separate kernels handle
  conv+silu, l2-norm and the gated RMSNorm.
- **Chunking.** Prompts run in 512-token chunks with state carried across
  them.

## Provenance: how the five repositories map in

Nothing was copied from the source repositories into the engine. Each role
was rewritten from SPEC.md.

| Repository | What it had | What it became here |
|---|---|---|
| **SemIf-OpenJev** (this repo, MIT) | Python decision contract, prompts, fixtures, committed results | The contract (SPEC §1-3, §5), byte-identical prompts, result schema. Its committed predictions are the acceptance test |
| **MLC** | C11 arena allocator and matrix/autograd for an MNIST MLP | `arena_t` and C float32 kernels (`base.c`, `cpu_backend.c`). Training and autograd are not needed for inference |
| **tinyweb-c** | Small C HTTP server with routes | `http.c`: `/v1/decide` and `/healthz`, Content-Length only, body limit, timeouts |
| **ML-model-language-predictor-** | FastAPI + scikit-learn pickle for language ID over HTTP | The serving role moved to `http.c`. Language ID becomes a decision (`examples/language.jsonl`). The pickle is 34 bytes (truncated or an LFS pointer), and unpickling untrusted files is unsafe, so it was not carried over |
| **ONNX** | Notebook: export PyTorch, compare outputs and latency | The parity-and-latency workflow became `tools/parity.py` (PyTorch vs engine) and `selftest` (CPU vs GPU plus prefill throughput). No ONNX runtime dependency |

"Clean room" here means spec first, then code. SPEC.md was written from:

- the checkpoint's public config, tokenizer and weight index;
- SemIf's contract;
- the published math;
- a reading of the Apache-2.0 `transformers` Qwen3.5 module. That reading
  pinned down details the config does not state: the zero-centred norm, the
  per-head query/gate interleave, the conv and head order, and the l2-norm
  epsilon.

The engine code was then written from SPEC.md, not transliterated. PyTorch
serves only as a numeric oracle in `tools/parity.py`. This was a single-author
spec-first process, not a legally audited two-team clean room.

## Differences from the draft `semif.h` / `semif.c` / `main.c`

The draft was a useful skeleton, but it did not match the pinned model or
SemIf's contract:

- **Architecture.** The draft assumed a Llama-style stack (36 layers, 32
  heads, vocab 152064). The pinned Qwen3.5-4B is hybrid: 32 layers in a 3:1
  pattern of gated-DeltaNet linear attention and gated full attention, 16/4
  heads of dim 256, partial RoPE (64 dims, θ=1e7), zero-centred RMSNorm,
  vocab 248320, tied head.
- **Prompt.** The draft used a custom `[0] id=... desc=...` template with
  digit markers. SemIf uses the ChatML template with a JSON payload, thinking
  disabled, and uppercase letters `A`..`P` as answer slots. Without byte
  equality `prompt_sha256` cannot match.
- **Tokenizer.** The draft's byte-fallback stub cannot produce real ids. This
  engine implements the real BPE and verifies it.
- **Weights.** The draft used raw per-tensor `.bin` blobs. This engine reads
  safetensors shards directly, so no export step is needed.
- **Input.** The draft's JSONL reader handled only two options and no escapes.
  This engine has a full JSON reader and 2-16 options.

## Known limits

- The CUDA path has not run on hardware yet. See the table above.
- Shared mode reuses the prefix serially, one suffix after another (SemIf's
  "serial prefix reuse"). Batched parallel suffixes, SemIf's fastest path, is
  the next step.
- The GEMM has no `cp.async` double-buffering. Attention runs on CUDA cores in
  float32. The KV cache is float32. These choices favour accuracy over peak
  speed.
- Text only: the vision tower and MTP head are ignored.
- The Unicode tables come from Python's unicodedata 14.0. Characters added in
  later Unicode versions may pre-tokenize differently from `tokenizers`.
- The server handles one connection at a time because the engine owns one GPU
  context.
